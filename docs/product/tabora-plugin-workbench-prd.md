# Tabora 插件化个人工作台 PRD

## 1. 产品概述

Tabora 是一个插件优先的个人工作台新标签页产品。它不是固定写死搜索、壁纸和卡片的新标签页，而是由插件装配出来的模块仪表盘型平台。

平台只提供插件运行内核、扩展点协议、宿主容器、存储、权限、事件、故障诊断和全局可达性保障。用户看到的搜索、卡片排列、背景、主题、卡片内容、弹窗和设置面板都来自官方或未来第三方插件。

核心哲学：**具体业务能力优先插件化**。widget、search、theme、background 都是插件；工作台整体布局壳体（rail + 命令搜索 + 主网格）由宿主内建提供，不再作为可切换的插件类型，只保留单一 dashboard，移动端为同一 layout view 的响应式断点（< 768px）。

## 2. 产品定位

Tabora 面向希望把浏览器新标签页变成个人工作入口的用户，强调可组合、可扩展和可持续演进。

核心定位：

- 模块仪表盘型个人工作台，而不是纯极简起始页或单纯搜索页。
- 默认体验由官方内置插件组合出来；平台不硬编码具体业务能力。
- 用户可以按自己的工作方式添加、删除、调整和配置插件实例。
- 插件生态可以逐步从官方插件扩展到本地可信插件，再扩展到第三方插件市场。

内建 Dashboard 布局是宿主内建的单一 dashboard 壳体：左侧轻导航 rail 承载工作台级入口，顶部命令搜索承载网页搜索与搜索源选择，主区域是可拖拽、可调整尺寸、可纵向滚动的逻辑网格。移动端（< 768px）在同一 layout view 内折叠 rail 为底部导航栏，不是独立布局。布局只决定"卡片怎么排列"和"搜索/导航怎么呈现"，不改变卡片内容、不干涉插件数据，并须满足 2.1.3 节「全局可达性约束」；具体尺寸以 `DESIGN.md` 为准。

不采用的方向：

- 不把 MVP 做成只有搜索框和快捷链接的新标签页入口。
- 不在 MVP 直接做复杂“今日流 / 日程驱动”产品，避免过早进入任务管理系统。

最高产品原则：

> 任何具体业务能力默认优先放进插件；平台只保留通用运行机制。

补充约束原则：

> 插件在约束框架内自由——平台定义边界和契约，插件在边界内自主。自由不意味着可以绕过权限、打破一致性或让用户迷失入口。

## 2.1 插件自由度与平台约束

平台为每一类插件定义清晰的**自由度**（插件能自主决定什么）和**约束**（插件必须遵守什么），确保即使未来有数百个 widget，用户体验仍然一致、可预测。

### 2.1.1 内建 Dashboard 布局的约束

- `topbar` 只接收一个 search 实例，搜索入口必须始终可达（常驻搜索栏 + 平台级 ⌘K 浮层）。
- `mainGrid` 接受 `widget`，卡片按逻辑网格排列并保证最小可读宽度（网格列数与尺寸以 `DESIGN.md` 为准）。
- rail 承载添加卡片、插件管理、设置、主题切换入口；这些入口也可通过 ⌘K 命令或设置中心到达。
- 移动端（< 768px）rail 折叠为底部导航栏；任何断点下都不允许横向滚动。

### 2.1.2 Widget 插件的约束

| 自由度                         | 约束                                                                  |
| ------------------------------ | --------------------------------------------------------------------- |
| 决定卡片内部内容的渲染         | 必须声明 `supportedSizes`（至少一个），实际尺寸在声明范围内由用户选择 |
| 决定卡片内部的交互逻辑         | 内容区不得撑破卡片外壳——过长时内部滚动或截断                          |
| 可以声明 modal/fullscreen 视图 | 弹窗/全屏只能通过 runtime context 请求宿主打开，不能自行创建全局浮层  |
| 可以读写插件私有数据           | 不得直接读写宿主 workspace 状态或其他插件的数据                       |

视觉与 token 约束（图标、theme token、控件复用）以 `AGENTS.md` 和 `DESIGN.md` 为事实源。

### 2.1.3 全局可达性约束

以下入口必须在工作台内始终可达，由内建 dashboard 布局和平台快捷键共同保证：

- 命令搜索：常驻搜索栏 + ⌘K 浮层，⌘K 为平台注册的全局快捷键。
- 添加卡片、插件管理、设置中心、主题切换：可通过 rail、顶部工具条、⌘K 命令或设置中心进入；设置面板由宿主 settings host 统一承载。
- 卡片上下文操作：每个 widget 卡片可通过右键菜单进入展开、尺寸调整和移除；卡片外壳不展示常驻 S/M/L/XL 尺寸切换按钮。

### 2.1.4 视觉一致性与错误隔离约束

- 主题 token 强制、暗色兼容、卡片状态稳定和 `@tabora/ui` 控件复用规则以 `DESIGN.md` 和 `AGENTS.md` 为事实源。
- 错误隔离产品要求：widget、布局、搜索、主题、设置面板任一失败都必须局部化，不白屏，失败区域显示可定位的错误或安全回退（详见 §8.14）。

## 3. 背景与问题

传统新标签页产品通常把搜索框、快捷链接、天气、便签、壁纸和主题做成固定功能。早期体验很直接，但后续会遇到几个问题：平台代码随功能增长越来越耦合、用户不能按插件维度自由组合、第三方生态难接入、各能力之间缺少统一扩展协议、单个功能出错容易影响整个页面。

Tabora 的产品假设是：新标签页应该是一个可装配的个人工作台，而不是一组固定组件。只要扩展点、运行时、权限和持久化边界设计清楚，默认体验和未来生态可以在同一套机制上演进。

## 4. 目标与非目标

### 4.1 产品目标

V1 MVP 要证明：

- 插件内核可以装配出完整产品体验。
- **平台约束体系**（全局可达性、响应式安全、视觉一致性）可以有效防止插件自由导致的体验碎片化。
- 官方插件可以组成默认工作台。
- 用户可以添加、删除、调整尺寸、配置和展开插件实例。
- 状态可以跨会话持久化。
- 插件渲染错误不会拖垮整个工作台。
- 外部能力调用通过权限桥进入宿主，不由插件直接越权执行。
- 官方插件 UI 使用统一基础组件和主题 token，避免每个插件重复实现控件样式。

### 4.2 非目标

MVP 不做：

- 第三方远程插件市场。
- 不可信远程插件沙箱运行时。
- 在线插件安装和自动升级。
- 云同步和账号系统。
- 团队或共享工作区。
- 插件评论、评分和审核系统。
- 完整插件开发者工具。
- AI 生成插件。
- 复杂 WebGL 背景编辑器。
- 深度移动端应用适配。

## 5. 目标用户

- **核心用户**：个人效率型用户，每天频繁打开新标签页，希望它承载搜索、快捷入口、便签、待办、天气、RSS、背景和主题，并按自己的习惯组合工作区。
- **次级用户**：插件开发者和高级用户，希望用插件扩展新标签页，需要稳定的 manifest、contribution、runtime context 和 storage 协议，未来可能发布本地或第三方插件。
- **内部用户**：产品和研发团队，需要快速扩展官方插件、保持平台与业务插件解耦，并用同一套协议支撑 apps/app 根工作台、浏览器扩展和未来其他 shell。

## 6. 用户价值

- 用户价值：把新标签页变成自己的工作入口，自由添加多个同类卡片实例、按支持尺寸调整布局、切换主题背景、展开插件视图，关闭重开后状态完整恢复。
- 平台价值：新能力通过插件扩展不污染核心，官方与未来第三方插件共用同一运行协议，安全、权限、持久化和故障隔离从 MVP 开始内建。

## 7. MVP 范围

### 7.1 包含范围

MVP 包含：

- 插件发现、manifest 校验、激活、registry、runtime context；扩展点 `widget`、`search`、`search-provider`、`background-provider`、`background-renderer`、`theme`、`settings-panel`。
- **内建 Dashboard 布局**（左侧轻 rail + 顶部命令搜索 + 逻辑网格），布局 view 渲染失败时显示具体错误、不隐藏故障。
- 官方内置插件包，以及 `@tabora/ui` 基础组件包，为官方与未来第三方插件提供一致的内容区控件。
- AI 文本基础设施：插件经权限范围内的 `context.ai` 调用服务端 gateway；云端内置模型需登录，Web/Extension 自定义 OpenAI-compatible provider 免登录且仅本机保存密钥，FNOS 仅支持设备管理员共享的自定义 provider。
- Widget 多实例、多尺寸、拖拽排序与网格状态持久化；卡片过多时纵向溢出策略；右键上下文菜单覆盖展开、尺寸调整和移除，卡片外壳不放常驻 S/M/L/XL 按钮。
- **分组（工作区）管理**：默认分组开箱可用，用户可在 rail 上创建、切换、重命名、改图标、改布局和删除分组，每个分组拥有独立实例集合和布局。
- 弹窗和全屏宿主、token 主题切换、背景来源与渲染器切换、搜索源启用禁用和默认搜索源。
- 轻量设置中心：宿主 settings host 聚合通用、外观、搜索、插件、关于五类信息，重能力后移。MVP 只有内置插件，设置中不展示插件权限。
- IndexedDB 本地持久化、插件错误边界和安全回退、`external-open` 最小权限桥。

### 7.2 官方内置插件

MVP 推荐官方插件：

- 内建 Dashboard 布局（与 theme/background/search 一样以 host builtin 注入，不是独立插件包）。
- `official.search.command-bar`：命令搜索 UI 和搜索编排，覆盖网页搜索、搜索源选择、快捷建议、常用命令和非阻塞反馈。
- `official.search-providers.basic`：Google、Bing、DuckDuckGo、GitHub 等搜索源。
- `official.background.providers.basic` / `official.background.renderers.basic`：基础背景来源与渲染。
- `official.theme.default-pack`：明亮和暗色主题 token。
- `official.widgets.productivity`：官方生产力 widget 套件，至少贡献快捷入口、待办列表、便签、天气四类卡片，每类以独立 contribution 注册。
- `official.plugin-manager`：插件设置面板，展示插件贡献能力、版本和启用状态。
- `official.settings.workspace`：轻量设置中心，聚合插件贡献的设置面板。

## 8. 核心功能需求

### 8.1 默认工作台

用户首次打开应用时，应看到一个完整可用的默认工作台。

要求：

- 默认工作台由官方插件装配，布局壳体由宿主内建 Dashboard 提供（左侧轻 rail、顶部命令搜索、主网格）。
- 默认实例包含快捷入口、待办、便签和天气；首屏优先露出这些核心模块与命令搜索（工作台规则以 `DESIGN.md` 为准）。
- 默认主题和背景来自插件 contribution。
- 平台代码不硬编码具体业务功能（widget、search、theme、background 仍是插件）；布局壳体不承载具体业务内容。

### 8.2 插件发现与激活

平台启动时完成插件装配。

要求：

- 扫描内置插件和已安装插件。
- 校验 manifest。
- 建立插件索引。
- 激活已启用插件。
- 插件通过 runtime context 注册视图和能力。

### 8.4 Widget 多实例

用户可以添加同一个 widget 插件的多个实例。

要求：

- 添加面板列出已启用的 `widget` contribution，MVP 至少含快捷入口、待办列表、便签、天气四类卡片。
- 用户选择 widget 后平台创建新的 `PluginInstance`，每个实例有独立 ID、尺寸、区域、位置和配置。
- 删除实例只影响该实例，不删除插件本体；创建或移除实例后宿主通过 Toast 给出非阻塞反馈。

### 8.5 Widget 尺寸调整

用户可以从插件声明支持的尺寸中选择实例尺寸。入口是卡片右键上下文菜单；卡片外壳不展示 S/M/L/XL 常驻按钮。

要求：

- 平台读取 `supportedSizes`，可选尺寸是 `S`、`M`、`L`、`XL` 的子集，Dashboard 把语义尺寸映射为列/行跨度（映射值以 `DESIGN.md` 为准）。
- 尺寸入口通过右键上下文菜单可达，菜单同时提供展开卡片和移除实例；卡片外壳不渲染标题 header，内容区由插件 view 满铺，移除操作以右上角悬浮按钮呈现。
- 键盘用户必须有替代尺寸调整路径（命令面板、详情视图或实例设置）。
- 尺寸变化更新实例状态并跨会话恢复。

### 8.6 拖拽排序与布局持久化

用户可以调整工作台卡片顺序。

要求：

- 支持在主网格拖拽排序，拖拽过程中提供实时换位反馈，不允许只在结束后突然跳位。
- 键盘用户必须有替代排序方式（可访问性要求见 `DESIGN.md`）。
- 排序结果写入 `PluginInstance.grid` 并跨会话恢复；布局数据和插件业务数据分开存储。

### 8.7 卡片溢出与首屏策略

当卡片超过一屏时，MVP 不压缩所有卡片强行塞进一屏，而是保持可读性和布局稳定。

要求：

- 主网格允许纵向扩展、超出视口时纵向滚动，不使用横向滚动作为默认溢出方案。
- 新增卡片默认追加到网格末尾，不打乱已有顺序；用户可通过拖拽和尺寸调整重新组织高低频卡片。
- 默认工作台只放少量核心卡片，低频官方卡片进入添加面板或设置中心。
- 移动端单列堆叠、保持语义尺寸状态。
- MVP 不做强制分页、复杂分组、自动收纳和卡片搜索。

### 8.8 轻导航 Rail

Rail 由宿主内建 Dashboard 布局定义其存在形式和交互语义（尺寸以 `DESIGN.md` 为准）。

要求：

- Rail 固定左侧、只放图标或极短标签，移动端折叠为底部工具栏且不造成横向滚动。
- Rail 包含主页、添加卡片、插件、主题切换和设置入口；这些入口也可通过顶部工具条、⌘K 命令或设置中心到达。
- Rail 承载分组（工作区）列表与"+"新建分组入口，按创建顺序排列、活跃分组高亮，前 9 个分组通过 `⌘1`–`⌘9` 切换（详见 §8.17）。
- Rail 不承载具体业务内容，内容通过 widget、search 或 settings-panel 插件呈现。

### 8.9 命令搜索

命令搜索是 Tabora 的核心交互入口。

要求：

- 搜索 UI 来自 `search` 插件、搜索源来自 `search-provider` contribution；Dashboard 搜索栏常驻主区域顶部，⌘K 由平台注册为全局快捷键、即使布局未放置搜索区也可触发浮层。
- MVP 支持搜索源选择、查询提交、实时内联建议和常用命令分组；搜索源下拉至少支持 Google、Bing、DuckDuckGo、GitHub。
- 搜索框支持 `@搜索源` 语法临时切换 provider（至少覆盖 `@github`）；键盘 `Enter` 执行、`Esc` 关闭/清空、`↑/↓` 结果导航。
- 打开外部 URL 必须通过 `context.permissions.openExternal`。

### 8.10 主题与背景

用户可以切换主题和背景。

要求：

- 主题来自 `theme` contribution，输出 token set 应用为 CSS custom properties；MVP 至少含 Sage Light 和 Sage Dark，通过 rail、命令面板和设置中心可达。
- 背景来源和渲染分别来自 `background-provider` 与 `background-renderer` contribution；MVP 至少含纯色、轻渐变和图片占位，由设置中心外观面板选择。
- 用户选择跨会话持久化。

### 8.11 轻量设置中心

MVP 应提供统一设置中心，但只覆盖插件化工作台闭环需要的最小设置能力。

要求：

- 设置中心由宿主提供标准容器，负责打开、关闭、导航、焦点管理和错误边界；信息架构为左侧分类导航 + 右侧内容区，MVP 至少包含通用、外观、搜索、插件、关于五类。
- 使用 `/settings/<section>` 路由；直接访问、分类切换和浏览器前进/后退都必须恢复对应面板。
- 设置内容来自已启用插件声明的 `settings-panel` contribution，宿主安全 renderer 通过 `@tabora/ui` 统一渲染；面板须声明支持的 `surfaces`（桌面/移动），schema 与 custom-view 契约以 `docs/technical/tabora-plugin-workbench-technical-design-v2.md` 为准。
- 桌面端双栏、移动端全屏单列（具体布局以 `DESIGN.md` 为准）。
- 面板职责：通用承载工作区摘要；插件展示名称、ID、版本、启用状态和贡献能力（关键官方插件可显示开关但限制关闭）；外观承载主题和背景选择并跨会话恢复；搜索承载默认搜索源和启用状态；关于展示版本、设计系统和扩展点摘要。
- 单个设置面板渲染失败时只显示该面板错误状态，不影响其他面板。
- MVP 不做设置搜索、导入导出、插件安装升级和复杂权限审计。

### 8.12 弹窗和全屏视图

插件声明支持弹窗或全屏时，用户可以打开对应视图。

要求：

- 插件只声明 view ID，平台打开标准宿主容器并在内容区渲染插件内容；插件不能直接创建全局弹窗或全屏视图。
- Widget 支持双击或右键菜单打开展开视图，展开后显示卡片标题、类型、实例 ID 和当前尺寸；支持 `Esc` 关闭并返回触发前焦点。

### 8.13 通知与快捷键辅助

MVP 需要提供轻量但统一的系统反馈和快捷键可发现性。

要求：

- 宿主提供 Toast 轻通知能力（多条堆叠、自动消失、必要时的 action）；主题切换、添加卡片、权限拒绝等关键操作提供非阻塞反馈。
- MVP 提供快捷键参考入口，至少覆盖 `⌘K` 命令面板、`⌘T` 切换主题、`⌘N` 添加卡片、`⌘,` 打开设置、`?` 快捷键面板、`Esc` 关闭、双击展开卡片和右键菜单。
- 插件不直接实现全局 Toast 栈或快捷键面板，而是通过 runtime context 请求宿主能力。

### 8.14 插件错误隔离

插件渲染失败时，只影响失败插件实例。

要求：

- Widget 渲染失败显示错误卡片，Modal/fullscreen 失败显示局部错误状态；同一工作台其他实例继续可用，错误状态保留实例 ID 便于定位。

### 8.15 本地持久化

工作区、实例、配置和插件数据需要跨会话保存。

要求：

- 使用 IndexedDB，工作区装配状态、插件实例、插件数据分表存储，插件业务数据按插件和实例命名空间隔离。
- 页面关闭重开后恢复工作区、实例、尺寸、位置、插件配置和插件数据。

### 8.16 插件 UI 一致性

MVP 应提供 `@tabora/ui` 基础组件包，作为官方插件和未来第三方插件的 UI 基线。

要求：

- `@tabora/ui` 面向插件内容区组件，不接管宿主级容器；宿主级结构（`WidgetCard`、`Modal`、`FullscreenHost`、`SettingsHost`、`WorkbenchRail` 等）由 shell/host 统一提供。
- 官方插件新增 UI 时优先使用 `@tabora/ui`，确需自定义时只在插件内部补充局部样式。
- 组件的依赖边界、theme token 使用、内建状态与可访问性规则，以及 MVP 组件清单，以 `AGENTS.md` 和 `DESIGN.md` 为事实源。

### 8.17 分组（工作区）管理

用户可以在同一应用内维护多个独立的工作台分组（group），每个分组保留自己的卡片实例、布局选择和视觉装配状态。分组是 MVP 已落地的工作区组织能力，区别于 V1.1 的"导入导出 / 跨设备 workspace 同步"。

要求：

- 平台默认创建一个不可删除的默认分组（`isDefault`，初始名称「我的工作台」），首次启动即可用。
- 用户可通过 rail 上的"+"入口、命令面板"新建分组"命令或 `⌘⇧N` 发起创建；使用就地命名交互（rail 出现占位按钮 + 浮出输入框，`Enter` 提交，`Esc`/失焦/空名取消），分组名上限 20 字符，首次自动按名称首字符生成默认图标。同时只允许一个就地命名流程，重复启动时聚焦已有输入框。
- 每个分组拥有独立的卡片实例集合、`instanceCounter`、活跃布局，并跨会话持久化；切换分组时在同一 Dashboard 布局中渲染该分组实例集合，非活跃分组状态不丢失。
- Rail 按创建顺序排列分组按钮，活跃分组高亮，hover 显示名称 tooltip，`⌘1`–`⌘9` 切换前 9 个。
- 每个分组按钮支持右键菜单：重命名、图标选择（内置图标集见 `DESIGN.md`）、删除分组；默认分组的"删除"项显示但置灰。
- 删除非默认分组时若仍有实例须先二次确认；删除后该分组实例和插件数据一并移除。
- 所有分组操作通过宿主 Toast 提供非阻塞反馈；分组管理由宿主直接承担，不引入新插件或扩展点。

## 9. 关键用户流程

### 9.1 首次启动

1. 平台内核启动。
2. 发现官方插件。
3. 加载默认 workspace 模板。
4. 挂载默认主题、背景、Dashboard 布局、命令搜索和默认 widget 实例。
5. 用户看到包含左侧轻 rail、顶部命令搜索和主网格核心卡片的完整工作台。

成功标准：页面直接可用，默认内容来自官方插件，首屏可见命令搜索与至少 4 个核心模块，无插件加载错误或空白页。

### 9.2 添加卡片

1. 用户通过 Dashboard rail、顶部工具区或 ⌘K 命令打开添加卡片面板。
2. 系统列出已启用 widget contribution，MVP 至少包含快捷入口、待办列表、便签和天气。
3. 用户选择 widget。
4. 平台创建实例并放入主网格；如果用户从某个非默认分组打开添加卡片面板，新实例同时追加到该目标分组的实例集合。
5. Widget 插件渲染卡片视图，宿主显示创建成功 Toast。

成功标准：新卡片立即出现在当前分组；从非默认分组添加时新卡片进入该分组，默认分组不受影响；多次添加同类 widget 生成多个实例，新实例跨会话保留。

### 9.3 调整卡片尺寸

1. 用户在卡片上打开右键上下文菜单。
2. 系统展示该 widget 支持的尺寸，以及展开卡片、移除实例等上下文操作。
3. 用户选择新尺寸。
4. 平台更新实例尺寸和网格跨度。
5. 卡片重新渲染。

成功标准：不展示插件未声明的尺寸，卡片外壳不展示常驻切换按钮，尺寸变化不破坏其他卡片，刷新后尺寸恢复。

### 9.4 卡片过多时继续使用工作台

1. 用户添加多个 widget 实例，主网格高度超过当前视口。
2. 新卡片追加到网格末尾。
3. 页面出现纵向滚动，用户可以向下访问低优先级卡片。
4. 用户把高频卡片拖到上方。
5. 用户把低频卡片调整为 S 或 M 尺寸。
6. 刷新页面后顺序、尺寸和位置恢复。

成功标准：卡片不被强行缩小到不可读，不出现横向滚动，添加新卡片不打乱已有顺序，首屏核心卡片优先可见。

### 9.5 使用命令搜索

1. 用户在 Dashboard 搜索栏或 ⌘K 命令面板输入查询。
2. 搜索插件展示当前搜索源和基础快捷建议。
3. 用户可通过下拉切换搜索源，或使用 `@github` 等 provider 前缀临时切换。
4. 用户提交查询或执行建议。
5. 搜索插件根据当前搜索源生成目标 URL，或触发添加便签、打开插件管理、切换主题等本地命令。
6. 外部搜索通过权限桥请求打开；本地命令通过宿主能力执行。

成功标准：空查询不触发搜索，外部打开通过权限桥发生，搜索入口保持首屏稳定位置且 ⌘K 全局可用，插件不直接依赖宿主内部实现。

### 9.6 使用轻导航 Rail

1. 用户点击 Dashboard rail 的添加卡片入口。
2. 宿主打开添加卡片面板。
3. 用户点击 rail 的插件入口。
4. 宿主打开插件设置面板或插件管理视图。
5. 用户点击 rail 的设置入口。
6. 宿主打开 settings host。

成功标准：rail 和顶部动作入口稳定、可聚焦、键盘可访问；rail 操作打开宿主容器而内容来自插件 contribution；移动端折叠后不产生横向滚动。

### 9.7 插件失败恢复

1. 某个插件视图渲染失败。
2. 宿主边界捕获错误。
3. 失败实例显示错误回退。
4. 其他实例继续可用。

成功标准：不出现整页白屏，失败状态能定位到实例，用户仍可操作其他卡片。

### 9.8 打开设置中心

1. 用户点击设置入口。
2. 宿主导航到 `/settings/<section>`，由路由打开设置页。
3. 宿主读取已启用插件贡献的 `settings-panel`。
4. 设置中心显示面板导航和当前二级路由对应的面板。
5. 用户切换到通用、外观、搜索、插件或关于面板；账号、同步等可选分类仅在相关插件已贡献时出现，并更新对应二级路由。
6. 宿主通过 provider registry + 默认 renderer 渲染 schema panel，或通过 view registry 渲染显式 `custom-view` panel。

成功标准：设置入口集中不散落；路由可直接访问，关闭/移动端返回回到工作台根路由，浏览器前进后退能恢复设置分类；面板来自插件 contribution 而非平台硬编码业务，宿主不为具体业务注入特例 API；设置面板失败不影响工作台和其他面板。

### 9.9 创建并切换分组

1. 用户在 Dashboard rail 上看到分组列表和列表底部的"+"按钮，或按下 `⌘⇧N`。
2. 平台在 rail 上插入一个脉冲态占位按钮，并在其右侧浮出就地命名输入框；输入框自动获得焦点。
3. 用户输入分组名（最多 20 字符），按 `Enter` 提交；按 `Esc` 或失焦取消，空名也视为取消。
4. 平台创建新分组：分配 ID、根据名称首字符生成默认图标、继承当前布局、初始化空实例集合，将新分组设为活跃分组并刷新 rail 与主区域。
5. 宿主通过 Toast 反馈"已创建分组「X」 · 右键可改图标"。
6. 用户右键点击 rail 上的分组按钮，宿主弹出上下文菜单：重命名、图标网格选择、删除分组（默认分组置灰）。
7. 用户点击其它分组按钮或按 `⌘1`–`⌘9`，平台切换活跃分组。

成功标准：默认分组开箱即用且"删除"项始终置灰；就地命名流程在 rail 上线性可见、不打开模态、同一时刻只有一个；切换分组后主区域立即重渲染、非活跃分组状态不丢失；所有分组操作通过 Toast 反馈并跨会话持久化。

## 10. 权限与安全需求

MVP 面向官方内置插件和本地可信插件，但权限模型必须从 V1 开始建立。

权限类型：

- `storage`：读写插件私有存储。
- `workspace`：读写工作区状态。
- `network`：访问外部网络。
- `clipboard`：读写剪贴板。
- `local-file`：通过用户授权流程读写本地文件。
- `external-open`：打开外部 URL。

授权原则：

- 默认允许插件私有存储、读取自身配置、注册 manifest 已声明的 contribution。
- 外部 URL 打开必须经过 `external-open` 权限。
- 未来 clipboard、本地文件、workspace write 等能力需要使用时授权。
- V2 前不接入不可信远程插件沙箱。

## 11. 数据与持久化需求

核心数据对象：

- `PluginRecord`：插件身份、版本、来源、启用状态、manifest 和授权权限。
- `Group`（工作区分组）：分组 ID、名称、图标、`isDefault` 标记、首选布局 ID、创建顺序、`instanceCounter`。
- `Workspace`：当前活跃 `Group` ID、分组列表（`Group[]`），以及活跃分组的当前布局、主题、背景和区域装配状态。
- `RegionState`：区域可接受扩展点和实例引用。
- `PluginInstance`：实例 ID、所属 `Group` ID、插件 ID、贡献 ID、区域、尺寸、网格位置和配置。
- `PluginDataRecord`：插件业务数据。

存储规则：

- 插件身份和权限不存页面位置。
- 插件实例存实例配置和位置，不存业务数据。
- 工作区存分组列表、活跃分组与各分组的装配状态，不存具体业务内容。
- 分组装配状态在 `Group` 维度隔离：删除分组时，仅删除该分组的实例引用与对应 `PluginDataRecord`，不影响其他分组。
- 插件业务数据按插件、分组和实例隔离。

## 12. 验收标准

MVP 验收条件：

- 打开应用后看到完整默认工作台，且它由官方插件装配出来。
- 当宿主内建 Dashboard 布局渲染失败时，平台显示“布局不可用”和具体错误，不用其他视图冒充当前布局。
- 默认工作台下，首屏包含快捷入口、便签、待办和天气中的核心模块。
- 搜索、添加卡片、插件管理、设置在任何布局下可达。
- 命令搜索支持 `⌘K` 唤起、Dashboard 搜索栏、搜索源下拉、实时建议、常用命令分组、`@搜索源` 临时切换、`Enter` 执行、`Esc` 关闭、`↑/↓` 结果导航。
- 平台代码不硬编码 Google URL、便签 UI、壁纸分类或待办行为等具体业务功能。
- 官方功能通过 manifest、contribution、runtime context、registry、permissions 和 plugin storage 实现。
- 官方插件内容区优先使用 `@tabora/ui` 基础组件，保持控件状态和可访问性一致。
- 用户可以添加同一个 widget 插件的多个实例。
- 用户可以从插件支持尺寸列表中选择每个 widget 实例的尺寸；尺寸入口在右键上下文菜单中，卡片外壳不展示 S/M/L/XL 常驻按钮。
- 用户可以通过拖拽或键盘替代方案调整卡片顺序，并获得稳定的实时反馈。
- 用户可以通过双击打开 widget 展开视图，并通过右键菜单访问尺寸、展开、移除等上下文操作。
- 当卡片数量超过一屏时，主网格可以纵向滚动，且不会出现横向滚动或不可读压缩。
- 插件声明支持弹窗或全屏时，用户可以打开对应视图。
- 用户可以通过插件 contribution 切换主题和背景。
- 用户可以打开轻量设置中心，并在通用、外观、搜索、插件、关于五类面板中切换，完成主题背景切换、默认搜索源配置和插件状态查看。
- 系统通过宿主 Toast 提供关键操作反馈，且快捷键参考入口可帮助用户发现核心操作。
- 插件渲染错误只影响失败的插件实例。
- 关闭并重新打开后，工作区、实例、尺寸、位置、插件配置和插件数据完整恢复。
- 默认分组开箱可用，不可删除；用户可通过 rail 上"+"或 `⌘⇧N` 启动就地命名流程创建新分组，前 9 个分组可通过 `⌘1`–`⌘9` 切换；rail 右键菜单覆盖重命名、图标选择和删除分组（默认分组项置灰），所有变更跨会话持久化。
